# Install & first sync (Swift)

Link `libsyncular` into a Swift target, create a `SyncularClient`, and sync one row between your app and the quickstart server.

::meta{for="iOS and macOS developers adding Syncular to a Swift target" time="15 minutes"}

:::terms
- **`libsyncular`**: The Rust core built as a C library. The `Syncular` Swift target calls its five functions.
- **xcframework**: The release artifact `Syncular.xcframework`, with iOS device, iOS simulator, and macOS slices.
- **Native transport**: The core's HTTP and WebSocket stack, compiled in by the `native-transport` feature.
:::

You need a Rust toolchain, a Syncular server (the [Quickstart](/quickstart/) server on port 8787 works), and a schema generated by `syncular generate` ([Schema & typegen](/guide-schema/)). Declare a `swift` output in `syncular.json` so typegen emits `Syncular.generated.swift`.

::::::steps
:::::step{title="Build the core" time="5 min"}
For local development, run the package gate. It builds the macOS dylib and copies it to `bindings/swift/vendor/`.

```sh title="terminal"
cd bindings/swift
./check.sh
```

For a shipping app, build the xcframework on a machine with full Xcode:

```sh title="terminal"
rust/scripts/build-native.sh apple
```

`build-native.sh` compiles with `native-transport` on, which `baseUrl` requires.

::checkpoint[`vendor/libsyncular.dylib` exists (local) or `rust/target/native` holds `Syncular.xcframework` (release).]
:::::

:::::step{title="Add the package" time="3 min"}
In a release app, consume the xcframework and drop the dev linker settings:

```swift title="Package.swift"
.binaryTarget(name: "CSyncular", path: "Syncular.xcframework"),
.target(name: "Syncular", dependencies: ["CSyncular"]),
```

`Sources/CSyncularFFI` is a verbatim copy of `rust/ffi.h` and the xcframework embeds the same header, so the Swift target compiles unchanged against either linkage. In local development, set `DYLD_LIBRARY_PATH=vendor` so the loader finds the dylib.

::checkpoint[`import Syncular` compiles in your target.]
:::::

:::::step{title="Create a client" time="3 min"}
```swift title="Sync.swift"
import Syncular

let client = try SyncularClient(
    schema: SyncularSchema.schema,
    config: SyncularConfig(
        baseUrl: "http://localhost:8787",
        dbPath: "\(appSupport)/syncular.db"
    )
)
```

The initializer creates the core, sends `create` with your schema, and starts the poll loop. Pass `clientId:` for an explicit id; without it the core generates one and keeps it in the database. Use a file path for `dbPath`: an in-memory database loses the outbox on restart. [Native client API](/native-client-api/#configuration) lists every `SyncularConfig` field.

::checkpoint[The initializer returns without throwing.]
:::::

:::::step{title="Write and sync" time="3 min"}
```swift title="Sync.swift"
try client.subscribe(id: "todos", table: "todos", scopes: ["list_id": ["groceries"]])
try client.mutate([.object([
    "table": .string("todos"), "op": .string("upsert"),
    "values": .object(["id": .string("t1"), "list_id": .string("groceries"),
                       "title": .string("Buy milk"), "done": .bool(false),
                       "position": .number(1), "updated_at_ms": .number(1)]),
])])
let result = try client.syncUntilIdle()
print(result, try client.pendingCommitIds())
```

::checkpoint[`pendingCommitIds()` prints `[]`, and the quickstart server holds the row. Run `bun run clients` from the quickstart to read it from a second client.]
:::::
